# Бариста — система отслеживания заказов

Приложение реализует требования ТЗ «Приложение для баристы в кофейне». Система написана на Python, использует Flask‑веб‑сервер и хранит данные в памяти, без БД. В комплекте — покрытие функциональности юнит‑ и интеграционными тестами (pytest, подход TDD).

---

## Быстрый старт

```bash
# 1. Активируйте виртуальное окружение (если ещё не активировано)
.\.venv\Scripts\activate

# 2. Установите зависимости
python -m pip install -r requirements.txt  # (если файла нет) python -m pip install Flask pytest

# 3. Запустите приложение
python main.py

# 4. Откройте браузер и зайдите на визуальный интерфейс
http://localhost:8000/ui
```

Логин баристы по умолчанию: `BaristaUser1`  
Пароль: `StrongPass1`

## Визуальный интерфейс (`/ui`)

Одностраничный интерфейс для баристы (чистый HTML+JS):

- Авторизация (кнопка «Войти»).
- Колонки активных заказов («К выполнению», «Выполняется», «Готов к выдаче») с сортировками по ТЗ.
- Колонки завершённых заказов («Получен», «Не получен», «Отменен»).
- Кнопки смены статуса согласно допустимым переходам.
- Кнопка «+5 минут» — продвигает операционное время, что триггерит напоминания и автоперевод «Не получен».
- Блок уведомлений (включая рассылку при готовности и напоминания).

## REST API

Корневой JSON с подсказками: `GET /`  
Все запросы (кроме `/api/login`) требуют заголовок `X-Session-Id`, полученный при авторизации.

| Метод | Эндпоинт | Назначение |
|-------|----------|------------|
| `POST` | `/api/login` | Авторизация сотрудника |
| `GET` | `/api/orders?section=active` | Список активных заказов (по статусам) |
| `GET` | `/api/orders?section=completed` | Список завершённых заказов |
| `POST` | `/api/orders/<order_id>/status` | Сменить статус заказа |
| `POST` | `/api/system/advance-time` | Продвинуть внутреннее время на N минут |
| `GET` | `/api/notifications` | Получить все отправленные уведомления |

**Формат входа / выхода** — см. `/` и автотесты.

## Соответствие требованиям ТЗ

| Требование | Реализация |
|------------|------------|
| FR-1,2,3,4,5 | Заказы хранятся в `OrderManager`. `GET /api/orders` возвращает сгруппированные по статусам заказы. Интерфейс `/ui` визуализирует их в колонках. |
| FR-6,7 | Сортировка «К выполнению» по приоритету/времени (`OrderManager.get_orders_grouped`). |
| FR-8 | Сортировка «Выполняется»/«Готов к выдаче» по времени перехода в статус. |
| FR-9 | Разрешения на смену статусов контролируются в `ALLOWED_TRANSITIONS`; UI показывает только допустимые кнопки. |
| FR-10,14 | Завершённые статусы автоматически попадают в соответствующий раздел. |
| FR-11,12,13 | При переходе в «Готов к выдаче» отправляется уведомление и планируются напоминания; через 90 минут статус меняется на «Заказ не получен». |
| FR-15,16 | При отмене оплаченного онлайн заказа создаётся запись на возврат и отправляется уведомление. |
| FR-17–23 | `AuthenticationService` проверяет логин/пароль и роль; после входа выдаёт доступ только к нужным разделам (бариста → управление заказами). |
| NFR-1,2,3 | Обновление реализовано через ручную кнопку/автоинтервалы; сортировки и хранение рассчитаны на десятки/сотни заказов. |
| NFR-4 | Все изменения сохраняются в памяти (при потере связи можно расширить до локального буфера). |
| NFR-5–9 | Функционал рассчитан на работу в современных браузерах; авторизация проверяется мгновенно, интерфейс отдаётся по HTTP (для продакшена требуется запуск за reverse proxy с HTTPS). |

## Архитектура

- `barista_app/models.py` — доменные сущности (заказ, сотрудник, перечисления).  
- `barista_app/order_manager.py` — бизнес-логика обработки заказов и уведомлений.  
- `barista_app/auth.py` — аутентификация и контроль доступа.  
- `barista_app/random_orders.py` — генератор случайных заказов.  
- `barista_app/webapp.py` — Flask-приложение, REST API и HTML-интерфейс.  
- `main.py` — точка входа, запускает Flask-сервер и генерирует стартовые заказы.  
- `tests/` — pytest‑тесты (юнит и интеграционное покрытие API).

## Тесты

```bash
python -m pytest
```

### Что проверяют тесты

- `tests/test_auth.py`
  - `validate_login_format`/`validate_password_format` — соответствие формату (12 символов, латиница/цифры; пароль с заглавной/строчной/цифрой).
  - `authenticate` — успешный вход, ошибки при неправильном формате и неверных данных, текст сообщений из ТЗ.
  - `sections_for_employee` — выдача доступных разделов по роли.

- `tests/test_orders.py`
  - Регистрация и группировка заказов в активных/завершённых разделах (FR‑1…FR‑5).
  - Сортировка «К выполнению» по приоритету и времени, а «Выполняется»/«Готов к выдаче» — по времени смены статуса (FR‑6…FR‑8).
  - Правила переходов статусов (FR‑9) и реакции на нарушения.
  - Уведомления при переходе в «Готов к выдаче», повторные напоминания спустя 5+3 минуты, автоперевод в «Не получен» через 90 минут (FR‑11…FR‑13).
  - Возврат средств при отменённом онлайн-оплаченном заказе (FR‑15).
  - Перемещение заказов в завершённые разделы (FR‑10, FR‑14).
  - Генератор случайных заказов — формат данных и базовые характеристики.

- `tests/test_web.py`
  - Интеграция Flask API: логин, защита эндпоинтов без сессии, сортировки активных заказов, допустимые переходы.
  - Проверка ручек `/api/orders`, `/api/orders/<id>/status`, `/api/system/advance-time`, `/api/notifications` на ожидаемое поведение и ошибки.
  - Сценарий «Готов к выдаче» → напоминание после сдвига времени на 6 минут.
